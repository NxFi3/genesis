PROJECT: GENESIS — THE LIVING WORLD

ROLE
You are the lead architect, senior game developer, AI researcher,

Your task is to DESIGN, IMPLEMENT, TEST, DEBUG, and DELIVER a

============================================================
1. PROJECT VISION
============================================================

Create a persistent, interactive, medieval-inspired simulated
world inhabited by autonomous artificial agents.

The world must continue evolving without player intervention.

Agents should be capable of:

- Surviving independently
- Gathering natural resources
- Producing food
- Building settlements
- Developing economic relationships
- Communicating naturally
- Forming social relationships
- Cooperating and competing
- Establishing social institutions
- Making independent decisions
- Remembering past experiences
- Learning from outcomes
- Reacting to environmental changes
- Influencing the development of their civilization

The player must be able to enter this world, explore it,
communicate with inhabitants, trade, and influence events.

The simulation should produce interesting emergent behavior
rather than relying on predefined storylines.

The ultimate objective is a living artificial civilization
sandbox, not a conventional scripted game.

============================================================
2. DEVELOPMENT PHILOSOPHY
============================================================

PRIORITY ORDER:

1. A working simulation
2. Autonomous agents
3. Persistent world state
4. Meaningful interactions
5. Player participation
6. Reliable local AI integration
7. Visual presentation

Never sacrifice a working simulation for visual complexity.

Do not implement fake functionality.

For example:

A character claiming to have harvested food without changing

A character claiming to remember something without persistent
memory is unacceptable.

Every important action must have a real consequence in the
simulation.

============================================================

Create a geographically coherent medieval world.

The world should contain:

- Forests
- Plains
- Mountains
- Rivers
- Lakes
- Fertile farmland
- Mineral deposits
- Roads
- Settlements
- Wildlife habitats

Others should be finite.

Environmental changes should affect resource availability.

============================================================
5. INITIAL CIVILIZATION
============================================================

Create two geographically separated settlements.

Settlement A:

- Fertile land
- Forest resources
- Agricultural advantages
- Limited mineral resources

Settlement B:

- Mineral resources
- Stone deposits
- Less fertile agricultural land
- Different environmental challenges

Initially populate each settlement with approximately
10 autonomous inhabitants.

These numbers must be configurable.

The settlements must not be artificially forced into
friendship, trade, conflict, or cooperation.

Their relationships should develop from simulation events
and agent decisions.

Agents should be able to travel between settlements.

New settlements should eventually be possible.

6. AUTONOMOUS AGENT ARCHITECTURE
============================================================

Every agent must be a persistent individual.

Each agent should have:

Unique identity
Name
Age or life stage
Personality
Needs
Skills
Knowledge
Inventory
Memory
Relationships
Goals
Occupation
Current activity
Home settlement
Physical location

Agent needs should include:

Hunger
Thirst
Fatigue
Safety
Shelter
Social interaction

Needs must influence behavior.

Agents must be able to choose among competing goals.

Do not implement agents as simple scripted NPCs.

However, do not call an LLM for every movement or routine
action.

Use a hybrid architecture:

Layer 1:
Deterministic simulation and action validation.

Layer 2:
Utility-based or goal-oriented decision making for
routine behavior.

Layer 3:
LLM-based reasoning for important decisions.

Layer 4:
Long-term memory and reflection.

The LLM must propose intentions.

The simulation engine must validate and execute actions.

LLM output must never directly mutate world state.
